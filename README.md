# 홀덤 AI 대전 (holdem-ai)

혼자(또는 친구 한 명과 함께) 규칙기반 GTO 스타일 AI를 상대로 즐기는 텍사스 홀덤 게임입니다.
Node.js + Express + Socket.io 기반이며, 호스트가 방을 만들면 AI들이 나머지 좌석을 채우고,
방 코드로 친구 1명이 추가로 합류할 수 있습니다.

## 주요 기능

- AI 인원수(0~7명), 시작 칩, 리바인 칩, 최대 리바인 횟수, 애드온, 시작 블라인드, 블라인드 상승 주기, AI 실수 빈도, AI 액션 텀을 방 생성 시 직접 설정 — 그리고 **방을 만든 뒤에도 방 안 설정(⚙) 화면에서 언제든 다시 바꿀 수 있습니다** (게임 진행 중에는 안전한 항목만 수정 가능)
- AI는 프리플랍 레인지표(포지션·인원수·스택 기반) + postflop 이퀴티/팟오즈 휴리스틱으로 행동 결정 (몬테카를로 시뮬레이션 기반 이퀴티 추정)
- 스택이 짧아지면 자동으로 푸시/폴드 전략으로 전환
- AI 난이도는 두 축으로 조절합니다: **AI 실력(0~100%)**은 매 판단마다 항상 적용되는 기본 판단 정밀도로, 낮을수록 손패 가치를 항상 어느 정도 잘못 평가하고(이퀴티 추정 몬테카를로 반복 횟수도 함께 줄어들어 판단이 더 흔들립니다), 높을수록(최대 100%) 반복 횟수가 늘어나 훨씬 정밀하게 판단합니다. **AI 실수 빈도(0~30%)**는 실력과 별개로 드물게 섞이는 "확 틀리는" 큰 실수(사람의 순간 방심/오판)를 재현합니다 — 실력을 100%로 둬도 실수 빈도를 0으로 낮추지 않는 한 가끔 실수를 합니다
- AI/사람 모두 베팅·레이즈 금액은 항상 100원 단위로 반올림됩니다 (10원/1원 단위 없음)
- 플랍 이후에는 팟의 30/50/70/100/150%를 한 번에 베팅할 수 있는 퀵버튼과, 직접 금액을 정하는 다이얼(슬라이더)을 함께 제공합니다
- 각 좌석의 포지션(UTG/MP/CO/BTN/SB/BB)을 이름표 옆에 표시합니다
- 데일리 게임처럼 시간 기반으로 자동 상승하는 블라인드 구조 (레벨업마다 스몰블라인드 기준 2배씩, 앤티 없음) — 또는 고정 블라인드
- AI 액션 사이에 최소 텀(기본 5초, 설정 가능)을 두어 진행 상황을 눈으로 따라갈 수 있게 하고, AI가 액션할 때/폴드했을 때 좌석 위에 말풍선·폴드 스탬프로 눈에 띄게 표시합니다. 다만 사람이 이미 전부 폴드해서 지켜볼 필요가 없는 핸드는 예전처럼 텀 없이 빠르게 진행됩니다
- 쇼다운/폴드로 핸드가 끝나면 보드·각자의 핸드·획득 금액을 보여주는 결과 화면이 뜹니다(쇼다운은 승자 순으로 정렬되고 승리 배지가 붙어 누가 어떤 패로 이겼는지 한눈에 비교할 수 있습니다). 핸드에 참여했다면(중간에 폴드했더라도) 자기 결과는 직접 확인하고 넘길 수 있도록, 참가한 모든 사람이 "다음 핸드 준비 완료"를 눌러야 다음 핸드로 넘어갑니다. 사람이 아예 참여하지 않은 핸드(전원 폴드 등)만 예전처럼 결과를 잠깐 보여주고 자동으로 진행됩니다. 파산해서 리바인을 선택해야 하는 경우에도 별도 팝업이 덮어씌워지지 않고, 결과 화면 안에서 바로 이어서 리바인 여부를 물어봅니다
- 올인으로 쇼다운까지 한 번에 진행되는 핸드는 남은 보드 카드를 한 장씩 순서대로(뒤집히는 애니메이션과 함께) 공개합니다. 지켜보는 사람이 없는 핸드(전원 폴드)는 예전처럼 텀 없이 바로 진행됩니다
- 베팅 금액은 슬라이더뿐 아니라 -/+ 버튼이나 숫자 직접 입력으로도 조절할 수 있고, 플랍 이후의 팟 비율(30/50/70/100/150%) 베팅은 레이즈·올인 버튼 사이의 "팟레이즈" 콤보를 눌러 고르는 방식으로 바뀌어 화면을 덜 차지합니다
- 파산 시 리바인 여부 선택: 호스트가 리바인을 거부(또는 최대 횟수 초과)하면 방 전체 종료, 게스트가 거부하면 게스트만 퇴장하고 게임은 계속. **최대 리바인 횟수가 0이면 리바인이 아예 불가능하다는 뜻입니다** (예전의 "0=무제한" 개념은 없앴습니다 — 무제한으로 하고 싶다면 충분히 큰 숫자를 넣어주세요). 애드온은 진행 중 1회 추가로 칩을 받을 수 있는 기능입니다
- **AI는 더 이상 자동으로 리바인되지 않습니다.** 파산한 AI 좌석은 비활성화 상태로 테이블에 남고("탭해서 리바인" 표시), 사람이 그 좌석을 클릭하면 리바인 여부를 확인하는 팝업이 뜨고, 확인을 눌러야만 리바인되어 다시 참여합니다(최대 리바인 횟수 제한도 동일하게 적용). 만약 남은 AI가 전부 파산해서 더 이상 핸드를 시작할 수 없게 되면, 방이 종료되지 않고 사람이 리바인시킬 때까지 조용히 대기합니다
- 화면 너비가 좁아지면 테이블이 세로로 길게 재배치되어 카드/베팅/팟이 서로 겹치지 않고, 화면 안에 다 들어오도록 높이도 자동으로 맞춰져 스크롤 없이 액션 버튼이 항상 보입니다. 휴대폰 가로모드에서는 세로형 대신 가로형 레이아웃을 그대로 유지하면서 크기만 줄여 맞춥니다. 베팅 슬라이더와 -/직접입력/+ 조작부는 세로로 두 줄로 나뉘어 있어 화면이 아무리 좁아도 서로 짓누르지 않습니다
- 방 코드는 영문·숫자 4자리이고, 로비 화면의 QR 코드를 카메라로 스캔하면 코드가 입력된 채로 참가 화면으로 바로 이동합니다
- 호스트 종료, 게스트 접속 끊김 시 자동 체크/폴드 처리(12초), 소켓 재연결 시 자동 재입장, 접속이 45초 이상 끊긴 채로 돌아오지 않으면 실제로 나간 것으로 정리(게스트는 퇴장 처리, 호스트는 방 종료)하는 등 방 운영 로직 포함. 재접속 시에는 그 사이 놓쳤을 수 있는 핸드 결과/리바인 확인/다음 핸드 대기 화면도 함께 복구되어, 모바일에서 화면 잠금 등으로 잠깐 접속이 끊겨도 게임이 멈춘 것처럼 보이지 않습니다

핸드 히스토리 열람 + AI 액션에 대한 GTO 코멘트 기능은 말씀하신 대로 다음 단계로 남겨두었습니다.

## 폴더 구조

```
holdem-ai/
  server.js                 Express + Socket.io 서버 (방/소켓 이벤트 라우팅)

  src/game/
    Deck.js                 카드 덱
    HandEvaluator.js        7장 중 최고 5장 핸드 평가
    GameEngine.js            베팅 라운드/사이드팟/쇼다운 상태머신
    BlindStructure.js        시간 기반 블라인드 레벨 스케줄 (스몰블라인드 2배씩, 앤티 없음)
    Position.js              좌석 순서 기반 포지션(UTG/MP/CO/BTN/SB/BB) 계산
  src/session/
    TableManager.js          방(테이블) 라이프사이클: 좌석, 리바인, 애드온, 설정 변경, 호스트/게스트, AI 자동진행(텀 포함), 결과 확인 대기
  src/ai/
    Equity.js                몬테카를로 이퀴티 추정 + 프리플랍 Chen 점수
    PreflopRanges.js          포지션/스택 기반 프리플랍 레인지 로직
    PostflopHeuristic.js      postflop 베팅/콜/폴드 휴리스틱
    AIDecisionEngine.js       위 로직을 묶어 실제 액션을 결정 + 안전장치(sanitize)
    util.js                  베팅/레이즈 금액을 100원 단위로 반올림하는 공용 헬퍼
  test/                      순수 Node 테스트 (아래 참고)
```

## 로컬에서 실행하기

```bash
npm install
npm start
# http://localhost:3000 접속
```

두 번째 사람과 테스트하려면, 서버를 실행한 뒤 방을 만들고 나온 "방 코드"를 다른 브라우저(또는 다른 기기, 같은 네트워크에서 서버 IP로 접속)에서 입력해 참가하면 됩니다.

## 테스트

핵심 로직(핸드 평가, 베팅 엔진, AI 의사결정, 방/리바인 라이프사이클)은 외부 의존성 없는 순수 Node 테스트로 검증되어 있습니다.

```bash
npm test
```

포함된 검증:
- 핸드 평가기 정확성 (로얄플러시~하이카드, 7장 중 최고 5장 선택, 킥커 비교)
- 베팅 엔진: 헤즈업/멀티웨이 액션 순서, 폴드 종료, 사이드팟, 최소레이즈 규칙, 무작위 200핸드 시뮬레이션에서 칩 총량 항상 보존
- AI 엔진: 300~500핸드 자동 시뮬레이션으로 크래시 없음 + 합리적인 VPIP/PFR 확인
- TableManager: 로비 구성, 게스트 합류, 호스트/게스트 리바인 거부 시나리오, 접속 끊김 자동처리

> 이 개발 환경(샌드박스)은 보안 정책상 `npm` 레지스트리 접근이 막혀 있어 `npm install`을 여기서 실행하지 못했습니다.
> 그래서 `express`/`socket.io`에 의존하지 않는 게임 로직·AI 부분은 여기서 직접 테스트로 검증했고,
> 서버/클라이언트 연결 부분은 표준적인 Express/Socket.io 사용법대로 작성했습니다. 사용자 환경(로컬 또는 Render)에서
> `npm install`은 정상적으로 동작할 것입니다. 혹시 실행 중 에러가 발생하면 알려주시면 바로 고쳐드릴게요.

## Render로 배포하기 (기존 워크플로와 동일)

이전 홀덤 딜링 앱과 같은 방식으로 배포하면 됩니다.

1. GitHub 웹 UI(또는 github.dev)로 새 저장소를 만들고 이 프로젝트 파일 전체를 업로드합니다. (`node_modules` 폴더는 올리지 마세요 — `.gitignore`에 이미 포함되어 있습니다.)
2. Render 대시보드에서 **New + → Web Service**를 선택하고 방금 만든 GitHub 저장소를 연결합니다.
3. 빌드 커맨드: `npm install`
4. 시작 커맨드: `npm start`
5. 배포가 끝나면 Render가 제공하는 URL로 접속해서 플레이하면 됩니다. 같은 URL을 친구에게 공유하면 방 코드로 함께 참가할 수 있습니다.

## 설정 옵션

방 만들기 화면에서 다음을 조절할 수 있습니다.

| 옵션 | 설명 |
|---|---|
| AI 인원수 | 0~7명 (호스트+게스트 좌석 2개는 항상 확보) — 게임 시작 전(로비)에서만 변경 가능 |
| AI 실수 빈도 | 0~30%. 실력과 무관하게 드물게 섞이는 "확 틀리는" 큰 실수의 빈도 — 게임 중에도 변경 가능 |
| AI 실력 | 0~100%. 매 판단마다 항상 적용되는 기본 판단 정밀도(낮을수록 항상 부정확). 기본값 75% — 게임 중에도 변경 가능 |
| AI 액션 텀 | AI가 액션하는 사이의 최소 대기 시간(초). 기본 5초 — 게임 중에도 변경 가능 |
| 시작 칩 | 최초 바이인 (기본 20000) — 로비에서만 변경 가능 |
| 리바인 칩 | 파산 후 리바인 시 채워지는 칩 (기본 = 시작 칩) — 게임 중에도 변경 가능 |
| 최대 리바인 횟수 | **0=리바인 불가.** 사람과 AI에게 공통으로 적용됩니다 — 게임 중에도 변경 가능 |
| 애드온 칩 | 0이면 비활성화. 진행 중 1회 추가로 받을 수 있는 칩 — 게임 중에도 변경 가능 |
| 시작 스몰/빅블라인드 | 1레벨 블라인드 (기본 100/200) — 로비에서만 변경 가능 |
| 블라인드 상승 주기(분) | 0으로 설정하면 블라인드가 고정됩니다. 상승 시 스몰블라인드가 2배씩 오르고 앤티는 붙지 않습니다 — 로비에서만 변경 가능 |

방 안에서는 ⚙ 버튼으로 언제든 설정 화면을 열 수 있고, 게임이 이미 시작된 뒤에는 좌석 구성·시작 칩·블라인드처럼 지금 판에 영향을 주는 항목은 잠기고 나머지만 즉시 반영됩니다.

AI는 파산해도 더 이상 자동으로 리바인되지 않습니다. 파산한 AI 좌석을 사람이 직접 클릭해서 리바인 여부를 확인·결정해야 합니다(최대 리바인 횟수 제한 포함). 사람(호스트/게스트)은 예전과 동일하게 파산 시 리바인 여부를 직접 선택합니다.

## 알려진 단순화 사항 (설계상 트레이드오프)

말씀하신 대로 "솔버급 완벽함"은 목표가 아니라서 아래처럼 실용적으로 단순화했습니다.

- 상대 레인지를 명시적으로 좁히지 않고 몬테카를로 이퀴티 계산 시 상대 홀카드를 무작위로 가정합니다 (정밀도는 낮지만 계산이 빠르고, 사람도 완벽한 레인지 리딩을 하지 않는다는 점에서 오히려 자연스러운 근사입니다).
- 프리플랍은 Chen 점수 기반 근사 점수제를 사용합니다 (공식 GTO 솔브 결과표가 아닌 규칙 기반 근사치).
- 숏 올인(최소레이즈에 못 미치는 올인)이 이후 플레이어의 리레이즈 권리를 제한하지 않는 경우가 있을 수 있습니다 (아주 드문 엣지케이스).
- 서버는 인메모리 상태만 사용합니다. 즉 서버가 재시작되면(Render 재배포 등) 진행 중이던 방은 초기화됩니다. 필요하시면 다음 단계에서 Supabase 등을 붙여 상태를 영속화할 수 있습니다.
- 동시에 여러 방을 지원하지만(같은 서버에서 여러 호스트가 각자 방을 만들 수 있음), 한 방에 사람은 호스트+게스트 최대 2명까지입니다.
